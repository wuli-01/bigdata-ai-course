🤖 AI Agent（智能体）

生成方式：按本仓库 Skill「concept-explainer」流程生成，AI 初稿 + 人工核查 · 生成日期 2026-09-08

💡 个人解释

在我看来，Agent 就是一个"接了活的实习生"：普通聊天机器人是"你说一句它答一句"，而 Agent 拿到目标后会自己拆任务、挑工具、动手干、看结果、再修正——整个过程不需要人在旁边一步步指挥。判断一个 AI 应用是不是 Agent，就看它有没有自主决定"下一步做什么"的能力。

⚙核心机制 / 组成

接收目标→ 读上下文（记忆）→ 规划下一步→ 调用工具行动→ 观察结果→ 循环或结束
  • 规划（Planning）：把大目标拆成小步骤，典型的推理范式是 ReAct（推理→行动→观察的循环）
  • 工具调用（Tool Use）：执行命令、读写文件、访问网页/API——没有工具的 Agent 只是"想"，有了工具才"能做"
  • 记忆（Memory）：短期记忆就是上下文窗口里的对话与工具结果；长期记忆靠外部存储检索回来
  • 循环与终止：Agent 在"思考-行动"循环里运行，靠条件判断（任务完成/达到步数上限/需要人工确认）退出
  • Anthropic 的建议：能不用 Agent 就不用——固定流程用"工作流（Workflow）"更可控，只有开放式多步任务才值得用 Agent

🎯具体应用场景（我自己的经历）

课程第一天，我让 AI 助手完成"安装 Git/Python/VS Code → 注册 GitHub → 建仓库 → clone/commit/push"的完整流程。它不是一次说完美步骤，而是边做边调整：发现我建仓库时把名字填成了 -，就引导我改名；push 遇到网络被墙，它先测了 5 个代理端口，又扫描可用 IP 修改 hosts；凭据管理器在我环境里崩溃，它换用 Python 直接调 Windows API 读取凭据。这种"遇障绕行、自主换方案"的多步执行，就是典型的 Agent 行为。

⚠易混淆问题 / 使用边界

容易混淆区别
Agent vs 普通聊天机器人机器人只做"一轮问答"；Agent 有目标、会拆解、能多轮自主行动
Agent vs 工作流（Workflow）工作流的步骤是人预先写死的；Agent 的步骤由模型在运行时自主决定
Agent vs Agent SkillAgent 是"干活的主体"，Skill 是给它的"说明书包"——主体与能力包的关系
  • 边界：高风险操作（删库、转账、对外发布）必须有人工确认；Agent 可能出错且难以预测，步数和权限要有上限
  • 误区："会调工具的就是 Agent"——关键是由谁决定调用顺序；流程写死的只是自动化脚本
