🤖 AI Agent（智能体）

一页速览 + 两关闯关测试 · 生成日期 2026-09-10

💡 我的个人理解

Agent 就是一个"接了活的实习生"：普通聊天机器人是你说一句它答一句，而 Agent 拿到目标后会自己拆任务、挑工具、动手干、看结果、再修正——不用人在旁边一步步指挥。判断一个 AI 应用是不是 Agent，就看它有没有自主决定"下一步做什么"的能力。

生活例子 🛵：外卖店的老板（用户）只说一句"把今晚的订单都送完"。普通店员会站在原地等你下一条指令；而一个靠谱的店员（Agent）会自己：看订单 → 排路线 → 骑电动车出发（工具）→ 发现某条路封了就换条路（看结果再调整）→ 送完回来报告。全程不用老板盯着。

⚙核心机制 / 组成

接收目标→ 读上下文（记忆）→ 规划下一步→ 调用工具行动→ 观察结果→ 循环或结束
  • 规划（Planning）：把大目标拆成小步骤，典型范式是 ReAct（推理 → 行动 → 观察 循环）
  • 工具调用（Tool Use）：执行命令、读写文件、访问网页/API。没有工具只能"想"，有了工具才"能做"
  • 记忆（Memory）：短期记忆就是上下文里的对话与工具结果；长期记忆靠外部存储检索回来
  • 循环与终止：在"思考—行动"循环中运行，靠条件（任务完成 / 步数上限 / 需要人工确认）退出
  • Anthropic 的建议：能不用 Agent 就不用——固定流程用"工作流（Workflow）"更可控，开放式多步任务才值得用 Agent
接目标——用户一句话交代任务
规划——拆步骤、决定下一步（ReAct）
用工具——执行命令/读写文件/访问 API
看结果——观察输出，错了就换方案
虚线圆表示循环持续转动，直到任务完成

🎯具体应用场景（我自己的经历）

课程第一天，我让 AI 助手完成"安装 Git/Python/VS Code → 注册 GitHub → 建仓库 → clone/commit/push"的完整流程。它不是一次性给出完美步骤，而是边做边调整：发现我把仓库名填成了 -，就引导我改名；push 遇到网络被墙，它先测了 5 个代理端口，又扫描可用 IP 修改 hosts；凭据管理器在它环境里崩溃，就换用 Python 直接调 Windows API 读取凭据。这种"遇障绕行、自主换方案"的多步执行，就是典型的 Agent 行为。

⚠容易混淆的问题 / 使用边界

容易混淆区别
Agent vs 普通聊天机器人机器人只做"一轮问答"；Agent 有目标、会拆解、能多轮自主行动
Agent vs 工作流（Workflow）工作流的步骤是人预先写死的；Agent 的步骤由模型在运行时自主决定
Agent vs Agent SkillAgent 是"干活的主体"，Skill 是给它的"说明书包"——主体与能力包的关系
  • 使用边界：高风险操作（删库、转账、对外发布）必须有人工确认；步数与权限要有上限
  • 常见误区："会调工具的就是 Agent"——关键是由谁决定调用顺序；流程写死的只是自动化脚本
