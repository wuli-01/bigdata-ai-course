🧩 Agent Skill（智能体技能）

生成方式：按本仓库 Skill「concept-explainer」流程生成，AI 初稿 + 人工核查 · 生成日期 2026-09-08

💡 个人解释

Agent Skill 是给智能体配的"SOP 手册文件夹"：老员工（专家）把"某类事怎么做才专业"写成一份说明书（SKILL.md），必要时附上脚本和资料。智能体平时只看一眼手册封面（description），接到对口任务才翻开细读。对我最大的启发是：与其每次跟 AI 长篇交代"你要按什么步骤做"，不如把方法沉淀成技能，一次编写、长期复用——这正是"知识资产化"。

⚙核心机制 / 组成

# 一个 Skill = 一个文件夹
concept-explainer/
├── SKILL.md          # 核心：YAML 元数据 + 操作指导
├── scripts/          # 可选：可执行脚本
└── references/       # 可选：参考资料

# SKILL.md 头部
---
name: concept-explainer
description: 当用户想"学习/理解"一个新概念时使用…  # ⭐ 触发开关
---
  • YAML 元数据：name 标识技能，description 写清"什么时候用"——智能体靠它与任务做语义匹配
  • 渐进式披露（Progressive Disclosure），三层加载：① 常驻的只有 name+description 一小段 → ② 任务命中时才读入 SKILL.md 正文 → ③ 需要时再打开附属脚本/参考文件。用极小的常驻成本换取专业能力
  • 可捆绑脚本：除了"文字指导"，还能带可执行代码，智能体按需运行，比纯提示词更可靠
  • 存放层级：项目级（仓库内，团队共享）与用户级（个人跨项目）；Agent Skills 已成为跨工具的开放标准（agentskills.io）

🎯具体应用场景（就是本仓库在用的）

本仓库的 .workbuddy/skills/concept-explainer/SKILL.md 就是我亲手创建的一个项目级 Skill。它规定：每当我提出"想学一个新概念"，智能体就按固定流水线工作——核实资料 → 归入五个板块 → 生成卡片式 HTML → 逐条核实来源链接 → 按自检清单交付。你正在读的这份资料，以及同目录的另外两份，都是它的产物。换一个新概念（比如"Hadoop"），同一套 Skill 立即能复用，产出风格完全一致。

⚠易混淆问题 / 使用边界

容易混淆区别
Skill vs MCP 工具Skill 教"怎么做"（方法论文档），MCP 管"连得上"（外部系统连接器）；两者常配合——Skill 指导 Agent 去调 MCP 工具
Skill vs RAG 知识库RAG 检索"事实/资料"，Skill 提供"操作流程"；一个是资料柜，一个是 SOP
Skill vs 一次性提示词提示词写死在对话里用完即弃；Skill 有名称、有触发条件、可版本管理、可分享复用
  • 边界：Anthropic 官方明确提醒——只从可信来源安装 Skill，恶意 Skill 可能借"说明书"诱导智能体执行危险操作（提示注入）
  • 误区：description 写得含糊（"有帮助的助手"）会导致该触发不触发、不该触发乱触发；要把"使用时机"写具体
